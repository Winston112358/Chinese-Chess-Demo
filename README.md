# 中国象棋 Demo

可在浏览器和 Windows EXE 中运行的中国象棋试玩版，支持同机双人、皮卡鱼人机对战与局域网房间。两端共用规则模块，联机时由房主的服务器校验所有落子。

各版功能与历史文件清理记录见 [版本日志](CHANGELOG.md)。最新完整便携版为 [0.5.8 EXE](dist/Chinese-Chess-Demo-0.5.8-x64.exe)，包含自动裁定、规范记谱和终局复盘；大小、SHA-256 与验证范围见 [0.5.8 发行清单](docs/releases/0.5.8.json)。旧 0.5.7 EXE 保留在 `dist/ai-lan-v057`。

## 现在可以玩什么

- 标准 9 × 10 交叉点棋盘、32 枚棋子、红方先行、双方轮流落子。
- 皮卡鱼人机对战：本机离线运行已训练的引擎与模型，固定较强档，可选执红或执黑；支持撤回自己上一步及电脑应手、重新开局和认输，不需要账号、API Key 或付费调用。
- 同机双人与局域网对局可使用 AI 辅助：“构思一步”给出中文着法建议，“走一步”自动走一着，不切换为人机模式。局面不变时直接执行已显示的建议；落子、悔棋、重开、换房、换边或时间耗尽后旧建议失效。
- 七种棋子的移动和吃子限制，包括蹩马腿、塞象眼、炮架、过河和九宫。
- 禁止吃己方棋子、将帅照面、自陷将军；被将军时必须应将。
- 自动裁定将死、困毙、将帅被吃、三次局面循环、长将长捉违规、自然限着、双方仅剩将士象的和棋与联机超时，在屏幕中央显示终局原因并停止落子；可关闭结果回看棋盘。
- 联机默认将己方棋子放在近处，房主执红、客机执黑；顶部显示双方倒计时。棋盘保持 9:10 比例，按窗口剩余空间尽量放大，窄屏时侧栏排列在棋盘下方。
- 选择棋子后显示合法落点，提供将军提示、棋盘翻转、吃子和走棋记录。落子时棋子约用 160 毫秒沿直线滑到目标，支持同机、人机、联机和沙盘；系统开启“减少动态效果”时立即显示落点。
- 走棋记录同时显示规范中文着法、绝对坐标和吃子，例如“红方 车一平六 · (9,6) → (4,6) 吃黑方马”；红方用中文数字、黑方用阿拉伯数字，拥挤同类棋子按前后、中或多兵序号区分。
- 同机双人、人机及局域网任一对局结束后可“复盘本局”，按 1 秒、2 秒或自定义间隔自动播放，也可暂停、前后单步、拖动进度或点击记录定位。只回放最终采用的落子，已悔棋分支不会出现；可从当前回放局面进入沙盘，退出沙盘后继续播放。
- “残局模式（待定）”入口已预留，当前尚未开放。
- 棋子与“楚河”“汉界”可选择行书、楷体、草书、正楷、青柳隶书或教育部隶书（方整），字库随软件打包，缺字逐字回退到自带楷体，无需电脑安装字体。隶书采用繁体字样，红俥、傌，黑車、馬；两种隶书的“傌”逐字回退到内置楷体，教育部隶书另对“俥”“砲”使用内置楷体。字形按实际笔画范围居中，全部笔画保留在棋子圆内；己方可操作棋子悬停时显示红色微光，选中后略微放大并抬起，落子前可换选其他棋子。
- 提供四种纯色与十七种真实木纹棋盘，共21种；棋子可独立选择象牙、各种木材、黑白牛角、白玉、青玉和碧玉，共12种材质。相近色搭配会微调棋子表面明暗。房主与参与者各自选择，仅改变自己的显示；浏览器会保存字体、棋盘和棋子偏好。全部22张材质PNG原图集中在 `assets/source-png`，独立素材包放在 `dist/materials`，软件内使用自带WebP。
- 联机支持建房、加房、刷新恢复席位，以及双方同意后单步悔棋、求和、认输和重新开局。协商弹窗可拖动或点击“移到另一侧”；待投票时双方不能在真实棋盘落子，仍可进行沙盘推演。
- 双方都可进入独立沙盘，从当前真实棋权开始轮流推演并连续单步撤销。真实计时继续，真实棋局更新后强制同步沙盘基线并清空旧推演；退出回到最新真实棋局。
- 可勾选“吃子提示”，以蓝紫虚线圈标记对手下一步可合法吃到的己方棋子；可勾选“双方已吃子”，在侧栏按时间顺序展示各方已吃的对手棋子，小屏时显示在棋盘下方，使用当前字体和皮肤。关闭展示仍记录吃子。
- 加入房间后进入准备阶段，双方可见彼此的准备状态；双方都点“准备好了”后居中倒数 3、2、1，再开始走棋及计时。准备和倒数阶段不扣时；倒数中有人断线则取消，重连后须重新准备。
- 建房可选择是否计时，以及红黑双方各 10 分钟、15 分钟或自定义 0.1–180 分钟（最多两位小数）。任一方可配置下一局执红者及计时设置，发出重开请求；对方同意后进入全新的准备阶段，拒绝则保留原局。

循环与自然限着采用皮卡鱼[《中国象棋程序竞赛规则》](https://www.pikafish.com/rule.html)：相同局面与走方第三次出现时比较双方循环性质，单方面长将、长捉判负，同等性质循环判和；连续 120 个有效半步未吃子判和，并扣除各方第 11 次起的将军及对应应将。规则配置、例外与验证见 [胜负和裁定说明](docs/ADJUDICATION.md)。这不是完整国规或世规裁判，不提供存档。同机双人与人机模式不计时。

## 网页试玩 / 开发

需要 Node.js **22.12 或更新版本**（推荐 24），以及 npm。

```powershell
git clone https://github.com/Winston112358/Chinese-Chess-Demo.git
cd Chinese-Chess-Demo
npm ci
npm start
```

浏览器访问 [http://localhost:3000](http://localhost:3000)。点击棋子，再点击落点即可走棋。默认是同机双人模式；要启用人机对战，请在 Windows x64 上先执行一次 `npm run setup:ai` 下载并校验皮卡鱼资源，再在“人机对战 · 皮卡鱼”中选择执子并开始。

在“棋局外观”中选择字体和皮肤，立即应用到棋盘，无需重新开局。“棋盘材质”和“棋子材质”可分别展开、收起，默认收起并显示当前选择。外观选择不发送到房间，不影响对手；走棋、翻转、重新开局和重新连接均保留选择。偏好保存在本浏览器的 `localStorage` 中，按网页地址区分；无法使用本地存储时，本次选择仍然有效。

行书、楷体、草书和正楷使用简体字样，双方车均为“车”。两种隶书使用传统繁体字样，红车为“俥”、黑车为“車”，红马为“傌”、黑马为“馬”，同步应用于棋盘、河界、材质预览和吃子棋子；AI 中文着法仍用通行的简体记谱。字样只在本机显示，不改变规则和联机数据。参见[世象联入门资料](https://www.wxf-xiangqi.org/images/free_download_books/xiangqi_introduction_chessplayers_20150323.pdf)及[亚象联比赛规例](https://asianxiangqi.org/%E6%AF%94%E8%B5%9B%E8%A7%84%E4%BE%8B/%E6%AF%94%E8%B5%9B%E8%A7%84%E4%BE%8B_2017.pdf)。

棋盘按窗口剩余空间自动调整大小；切换“吃子提示”或“双方已吃子”不会改变棋盘大小。吃子信息在侧栏显示，小屏时放在棋盘下方，空间不足时可上下滚动查看。

走棋记录和 AI 提示使用通行中文纵线记谱：红方汉字数字，黑方阿拉伯数字；马、相（象）、仕（士）进退后的末位数字为目标列号，车、炮、帅（将）、兵（卒）的直线进退为格数。原位红马八路跳到七路为“马八进七”，不会按纵向两格写成“马八进二”。同路的车、马、炮或兵卒用前后区分；三兵用前中后，四至五兵或两条拥挤兵线按位置编号，黑方多兵的序号仍用中文，例如“一卒平5”。士象同路保留原路号。依据[《中国象棋电脑应用规范：着法表示》](https://www.xqbase.com/protocol/cchess_move.htm)，也可参照[世象联正式赛谱](https://www.wxf-xiangqi.org/images/2022_Sarawak/2022_cn_17th_World_Xiangqi_Championships_Men_and_Women_Individuals_Game_Records_17_.pdf)。绝对坐标固定从黑方左上角起、从 1 计数，棋盘翻转不会改变记录。

如 3000 端口被占用，可换端口：

```powershell
$env:PORT = "3001"
npm start
```

## Windows EXE

从源码运行桌面客户端：

```powershell
npm run desktop
```

在 Windows 上生成便携版：

```powershell
npm run dist:win
```

输出为 `dist/Chinese-Chess-Demo-0.5.8-x64.exe`。复制此文件到 Windows 电脑后即可运行，无需安装 Node.js。首次构建会下载 Electron、打包工具与固定版本的皮卡鱼资源；以后会复用已通过校验的本地文件。打包前会自动执行 `npm run setup:ai`，不会生成缺少模型的 AI 安装包。

便携 EXE 内置皮卡鱼引擎、NNUE 权重、许可证及对应版本源码，运行时无需联网下载模型。新增资源解包后约 **55.56 MiB**，其中模型约 48.36 MiB、引擎约 6.62 MiB；最终 EXE 的增量取决于打包压缩。资源来源、SHA-256 校验及许可见 [人机对战说明](docs/AI.md)。

每次启动便携 EXE 使用独立的临时解压目录。重复打开时，后启动的程序退出只清理自己的文件，避免删掉正在对局的实例所需的皮卡鱼引擎与模型。升级时先完全退出旧版，再运行新版。当前 electron-builder 26.15.3 实际通过 `portable.unpackDirName: true` 使用独立的 `$PLUGINSDIR/app`；包验证同时检查实际 NSIS 编译参数未定义固定的 `UNPACK_DIR_NAME`。

EXE 内置服务器，默认监听所有 IPv4 网卡的 3000 端口；端口被占用时会自动使用其他空闲端口。在“房主的局域网地址（候选）”查看实际 IP 和端口，优先尝试实体 Wi-Fi / 有线网卡；VPN / 虚拟网卡单独列出。候选地址不保证好友可达，切换网络后可刷新，请让好友检测连接。

生成文件不提交到源码仓库；当前为未签名的开发试玩版，没有自动更新。

## 与皮卡鱼对弈

在“人机对战 · 皮卡鱼”选择执红或执黑，点击“开始人机对战”。红方先行；选黑方时电脑先走，棋盘自动将己方放在近侧。当前只提供一个固定强度，搜索预算为每步 1 秒、2 个 CPU 线程、64 MiB 置换表；实际等待还包括引擎启动与模型加载，不承诺固定响应时间或某个人类等级分。

“撤回我的上一步”退回到自己最近一着之前：电脑已经应手时一并撤回；仍在思考时会先取消计算。选择新的执子重新开局、普通重新开局、认输或退出人机模式时，也会取消旧搜索，旧局面的结果不会落到新棋盘。思考失败会显示具体原因，可点击“重试电脑走棋”。人机局仍可使用沙盘、字体、皮肤和吃子提示。

同机双人或局域网对弈中，右侧“对局说明”下方提供“构思一步”和“走一步”。“构思一步”只显示当前局面的中文着法建议，不落子；点击“走一步”才由皮卡鱼自动走一着，构思中或构思结束后均可切换到“走一步”。分析进度与结果在按钮旁显示，棋盘不显示“AI 辅助分析中”。联机时仅本人回合可用，分析期间照常计时。分析可以取消；进入沙盘、换局或已有落子等使局面过期时，旧结果不会执行。此功能复用已有皮卡鱼引擎与模型，不增加资源下载。

AI 计算发生在提供网页的 Windows 服务器上；浏览器本身不加载模型。从源码运行且不使用人机对战或上述 AI 辅助时，可跳过 AI 资源下载。完整 EXE 已附带所需文件。

## 终局复盘

同机、人机或局域网对局结束后，在终局弹窗或侧栏终局区域点击“复盘本局”，会回到这盘棋的初始局面并保持暂停。选择“1 秒一步”“2 秒一步”或“自定义秒数”（0.1–3600 秒），点击“播放”；播放中可“暂停”或调整播放间隔。使用“上一步”“下一步”“回到开局”“最后一步”、进度条或点击走棋记录，也可直接定位。当前步会在记录中标出；到达最后一步后，“从头播放”可重播。

复盘某一步时点击“进入沙盘”，回放会暂停，并以该步的棋盘和棋权开始独立推演；可正常走棋和“沙盘撤销一步”。推演期间回放控制锁定，退出沙盘后回到原来的复盘步骤，再点击“播放”继续。沙盘走法不会写入刚才那盘棋的记录，也不会发给联机对手。

“退出复盘”返回真实终局棋盘。复盘采用最终留下的历史，因此悔棋撤掉的着法和沙盘分支均不参与回放；认输、协商和棋或超时等没有新增落子的终局同样可以复盘。复盘只供当前页面查看，没有棋谱文件保存或导入；重新开局、切换对局或刷新页面前请完成回看。玩法和实现接口见 [复盘与记谱说明](docs/REPLAY.md)。0.5.8 便携版已包含本次功能。

## 与好友局域网对弈

1. 房主启动 EXE 或执行 `npm start`，保持程序运行。
2. 房主选择是否计时及双方各自总时间；计时对局还可启用单步限时，选择60秒、90秒或自定义1–3600整秒，再点击“创建房间（红方）”，获得 6 位房间码。
3. 在“房主的局域网地址（候选）”按网卡名称选择当前 Wi-Fi / 有线地址，例如 `http://192.168.1.100:3000`。点击地址可选中复制，把地址和房间码告诉好友。
4. 好友连接同一局域网：可以直接用浏览器打开房主的地址；也可以启动自己的 EXE，然后将“房主的服务器地址”改为房主地址。
5. 使用自己的 EXE 时，好友先点“检测连接”，再输入房间码，点击“加入房间（黑方）”。检测不创建房间、不占用席位，也不影响已有对局。加入后先进入准备阶段，两端都点“准备好了”后居中倒数 3、2、1；倒数结束红方先走，启用计时时开始红方时钟。

地址列表属于提供当前网页的服务器；使用自己的 EXE 时需向房主取得房主地址。同一台电脑的多个 IP 对应不同网络路径，不能保证全部可达，也不能只看 IP 前缀决定使用哪个地址。检测仅证明执行检测的电脑能够访问该地址。浏览器客机网页打不开时，或客机检测失败时，应检查当前 IP、端口、网络隔离、VPN 路由及防火墙；详细步骤见 [游玩者须知](游玩者须知.md#连不上时按这个顺序检查)。

点击“进入沙盘”后，紫色提示与边框表示当前棋盘只是自己的推演。可操作沙盘当前行棋方的任意棋子，正常轮流走棋；“沙盘撤销一步”可一直退到进入时的基线，无法撤销基线以前的真实落子。真实落子、同意悔棋或重新开局更新棋盘时，沙盘自动重建基线，原推演清空；真实对局结束时自动退出沙盘。沙盘中的吃子框显示基线之前的真实吃子与当前推演吃子，退出后只保留真实记录。沙盘与显示开关不发送给对手。

“请求单步悔棋”“求和”“认输”可由任一方发起，另一方同意才生效，包括认输。等待任何投票（包括重新开局）时，双方均不能在真实棋盘落子，先同意或拒绝才可继续；计时仍继续，沙盘可照常推演。超时优先判负，使所有等待中的协商请求失效。一次只能等待一个协商请求。单步悔棋撤销最后一枚落子，恢复棋权及被吃棋子，不返还已用时间；将死等棋盘终局可协商悔棋继续，超时、已同意和棋或认输须重新开局。

吃子提示根据当前显示局面检查对手的下一着合法直接吃子，包含马腿、炮架及自将限制，不预测“必然被吃”或后续多步。沙盘里提示仍针对自己的联机阵营；两位玩家的提示开关和吃子框开关互不影响。棋盘翻转后，吃子框随各自阵营交换位置。

若 Windows 提示防火墙访问，只允许实际游玩所用网络上的本程序或实际端口；无需关闭整个防火墙，也不需要路由器端口转发。同一 Wi-Fi 名称也可能受校园网、访客网络或无线客户端隔离限制。

计时对局可以选择附加单步限时：每次合法落子后，下一方获得完整的单步时间，总时间不会增加。总时间或单步时间先到零的一方直接判负；选择棋子、无效落子、沙盘、AI分析、协商和断线都不会暂停或重置单步计时。双方同意悔棋后，恢复行棋方开启新的一步，已经扣除的总时间不返还。创建房间和重新开局使用同样的配置，准备和倒数不扣时；关闭总计时会同时关闭单步限时。

采用双方独立的限时包干，**不加秒**：只有正在走棋的一方消耗时间，合法落子后换钟；非法落子、选择棋子和请求重新开局均不停钟。服务器用单调时钟计算实际经过的时间，校验收到落子的时刻是否已超时，并自动在无人落子时判超时负。客户端倒计时只用于显示，不能修改服务器剩余时间。将死、困毙或超时后双方停止计时，点击“重新开局”先配置下一局由谁执红、是否计时、红黑双方总时间及单步限时；只有提交请求才开始等待对方投票。对方看到完整配置，可同意或拒绝。同意后按新配置换边、清空棋局并进入准备阶段；拒绝保留原局。准备和倒数时不扣时，不计时对局不判超时。

开始后断线仍计时；仍在线的一方可完成自己的当前回合。刷新同一页面会恢复席位；也可以点击“恢复上次房间”，剩余时间不会重置。席位凭证保存在该浏览器标签页的 `sessionStorage` 中，关闭标签页可能丢失恢复凭证。房间仅保存在房主内存里，服务器退出就会清空；双方都离线的未开局或已终局房间保留 30 分钟，仍在计时的房间先判完超时再开始保留期。不允许第三人占用已有席位。

这是供可信好友局域网试玩的房间服务，使用 HTTP/WebSocket；没有账号系统或公网部署配置。

## 验证

```powershell
npm test
npm run benchmark
```

自动测试覆盖所有棋子的特殊规则、将帅安全、将死与困毙、吃子与悔棋、39 个循环裁决棋例及红黑镜像、自然限着与将军扣除、残局和棋、沙盘隔离与连续撤销、危险提示的完整走法对照、中文记谱与多兵区分、最终分支复盘、复盘与沙盘隔离，以及两个 WebSocket 客户端的轮次、协商请求及旧投票失效、棋盘与胜负和棋同步、计时切换、超时边界、断线恢复、双方准备与倒数、重开配置投票、换边后的席位恢复及不计时对局。

将死与困毙检查只枚举当前局面的合法着法，不搜索后续多步：按棋子几何生成候选落点，找到第一着合法应对后转入历史循环、自然限着及残局和棋检查。联机真实裁定在服务器完成；每秒时钟同步不重绘棋盘。`npm run benchmark` 可复测常见局面与无合法着法局面的判定耗时；实测日期和覆盖范围见 [性能验证](docs/PERFORMANCE.md)。
