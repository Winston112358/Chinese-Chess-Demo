# 自动胜负与和棋裁定

本项目的循环与自然限着采用皮卡鱼社区发布的[《中国象棋程序竞赛规则》](https://www.pikafish.com/rule.html)，查阅日期为 **2026-10-04**。这是程序竞赛规则配置，部分循环棋例的处理与《世界象棋规则》及中国象棋竞赛规则不同，不能视作完整国规或世规裁判。

同机双人、人机、联机及沙盘共用裁定逻辑；联机真实棋局以房主服务器的结果为准。屏幕终局提示会说明原因并停止继续落子。沙盘只裁定自己的推演，对真实对局结果没有影响。

## 循环局面：长将、长捉及允许循环

棋子的位置、种类、颜色及轮到哪方走都相同的局面，在同一局中出现第三次时触发裁定，开局本身也计作一次。裁判只分析这三次之间的着法，并把序列首尾相接。

| 循环性质 | 等级 | 判断依据 |
| --- | ---: | --- |
| 长将 | 2 | 该方在循环中的每一步都将军 |
| 长捉 | 1 | 循环完全没有将军；该方每步都捉同一枚对手棋子，对手每步都使这枚子逃捉 |
| 允许循环 | 0 | 不符合上述两种情况 |

双方等级相同判和；等级较高的一方判负。因此，**单方面长将、单方面长捉判负，双方长捉或双方长将可以判和**。轮流捉不同棋子、捉住后对方没有每步逃捉，以及夹有将军但未构成长将的循环，不会按长捉判负。

“捉”以合法吃子为基础，考虑将帅安全、牵制、蹩马腿及炮架。吃掉目标后能够被对手合法回吃的攻击通常不算捉；马或炮攻击车，以及士或象攻击车、马、炮，按规则例外处理。帅、将、兵、卒的攻击不算捉；未过河兵卒不能成为被捉目标；同类棋子能相互合法吃掉的情况也不算捉。

记录会追踪同一枚棋子，即使两枚同类棋子互换位置，或联机数据经过 JSON 序列化，也不会把它们当成同一被捉目标。判重复时则按棋盘局面比较，同类棋子交换位置不会阻止相同局面计数。

## 自然限着与残局和棋

- 连续不吃子达到 **120 个有效半步**判和。“半步”指一方走一次，通常相当于双方各走 60 次。
- 在这一段内，各方只有前 10 次将军计入限着；后续将军及其对应应将都扣除。连续反将产生的扣除重叠只扣一次。
- 吃子清零限着及双方将军次数。兵卒前进或横走仍计入，不会重置限着。
- 棋盘上双方都只剩将帅、士仕、象相时自动判和。有车、马、炮或兵卒仍在场，不仅凭子力少就自动判和。

将死、困毙优先于自然限着；三次局面循环也优先于自然限着。因此，第 120 个有效半步同时形成将死时仍判胜负，同时形成循环则按循环性质裁定。

## 结果与悔棋

| `reason` | 结果 |
| --- | --- |
| `general-captured`、`checkmate`、`stalemate` | 将帅被吃、将死、困毙的一方负 |
| `perpetual-check`、`perpetual-chase` | 单方面长将、长捉违规的一方负 |
| `repetition` | 相同违规等级的三次循环，和棋 |
| `no-capture` | 自然限着，和棋 |
| `insufficient-material` | 双方仅剩将帅、士仕、象相，和棋 |

和棋结果使用 `{ winner: null, loser: null, reason }`；胜负结果保留双方颜色。计时超时、协商求和和认输继续按对局模式处理。棋盘自动终局可以悔棋恢复；联机需要对方同意，计时不返还。

限着和循环依据现有走棋记录重建，悔棋同步恢复其计数，不增加存档功能。软件仍没有实现赛场裁判的全部判例、非法着法处罚、比赛用时制度及申诉流程。
