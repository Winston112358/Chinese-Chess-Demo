## 实现的基本规则

棋盘为 9 列、10 行，棋子在交叉点上走动。双方各 16 枚棋子，红方先行，一次移动一枚棋子。落在敌方棋子的位置即吃子，不能落在己方棋子的位置。

| 棋子 | 走法和限制 |
| --- | --- |
| 帅 / 将 | 九宫内沿横线或竖线走一格。两将帅不能在同一列无子相隔。攻击判断包含飞将。 |
| 仕 / 士 | 九宫内斜走一格。 |
| 相 / 象 | 斜走两格，象眼必须为空，不能过河。 |
| 马 | 走日字；先直走方向紧邻的交叉点有棋子时，马腿被堵。 |
| 车 | 沿横线或竖线走任意格，路径不能有棋子。 |
| 炮 | 不吃子时沿直线移动，路径必须为空；吃子时与目标之间恰好隔一枚任意颜色的棋子。 |
| 兵 / 卒 | 未过河只能前进一格；过河后也可横走一格。始终不能后退、斜走或升变。 |

程序模拟落子后的棋盘，检查己方将帅是否受到攻击；任何导致己方将帅被攻击或将帅照面的落子都会被拒绝。处于将军状态时也使用相同检查，因此只能应将。攻击检测考虑炮架、马腿和象眼。

内部坐标从黑方左上角开始：`x = 0..8`、`y = 0..9`。红方前进为 `y - 1`，从 `y <= 4` 开始视为过河；黑方前进为 `y + 1`，从 `y >= 5` 开始视为过河。九宫列为 `x = 3..5`，黑方行 `0..2`，红方行 `7..9`。界面记录使用从 1 开始的坐标，翻转棋盘不会改变记录坐标。

## 自动胜负判定

每次合法落子后检查轮到的一方。如果其将帅已经被吃，则立即判负；否则检查其所有棋子是否有至少一着合法走法。若没有合法走法，正在被将军为将死，未被将军为困毙；**两者都判负**。检查包括移将、吃攻击子、挡将、移开炮架等所有合法救应，不能只检查将帅本身的移动。普通将军仍可应将时不会提前判负。

判定只处理当前局面，不搜索几步后的必胜。按棋子真实运动几何生成候选落点；马至多 8 个，象、士至多 4 个，兵卒至多 3 个，车炮沿 4 条射线扫描并在阻挡处剪枝，将帅额外检查飞将。找到任意一着合法应对即提前退出。每个候选仍使用同一将帅安全校验，避免为了性能漏判。固定 90 点棋盘、每方至多 16 子，检查量有固定上界，不存在随搜索深度指数增长的游戏树。

联机中只由服务器判定胜负，浏览器落子前只做单步校验；周期倒计时消息不重新计算走法、不重绘棋盘。终局后停止走棋，双方同意后可以重开；将死、困毙或将帅被吃后可协商撤回最后一着并继续。超时、已同意求和或认输不能用悔棋重开。

## 局域网计时

采用第 6 条的限时包干思路，双方拥有独立的全局总时间，本版无每步加秒或多阶段时限。房主分别选择每方 10、15 或自定义分钟（0.1–180，最多两位小数）；好友不能更改已创建房间的时限。

以下是本软件明确采用的联机约定：

1. 双方首次连接齐后，红方先行并开钟；等待好友时不扣时间。
2. 只扣当前行棋方的时间，服务器接受合法落子后切换另一方时钟。服务器收到落子时，若该方剩余时间已到零，先判超时负，拒绝这一步。
3. 非法落子、选择或更换棋子均不停钟。倒计时无人操作也会自动判负，无需对手提出请求。
4. 将死、困毙、将帅被吃或超时立即终局并停钟。
5. 开局后断线不停钟；仍在线的一方可完成当前回合。恢复席位同步现存棋局、结果和剩余时间，不重新给时。房主服务器关闭会清空房间。
6. 请求重新开局后，双方不能落子，须先投票；计时仍继续。双方同意才清空棋局并恢复本房间两方初始时间，红方重新开钟。
7. 沙盘推演不换真实对局的时钟。悔棋、求和或认输请求等待对方投票时，双方不能在真实棋盘落子，沙盘可继续推演，计时不停；服务器先检查超时，再处理投票。
8. 双方同意单步悔棋后恢复上一步之前的行棋方并换钟，双方已经用掉的时间不返还。求和与认输也须对方同意，同意后结束棋局并停钟。

时钟使用服务器的单调时间，避免系统校时或修改电脑时间改变剩余时间；显示端使用本地单调时间插值并定期接收校准。最终以服务器判定为准，不使用客户端上报的时间。

## 沙盘和提示

沙盘从当前真实局面的棋权开始，复制棋盘后用同一规则交替操作双方；单步撤销恢复相应行棋方与被吃棋子，只可撤销沙盘历史。真实棋局更新后沙盘复制最新局面，清空推演；退出回到真实对局。其落子不发送给服务器，真实计时继续。

吃子提示检查敌方在当前显示棋盘的下一步合法直接捕获，排除自将和不符合棋子走法的捕获，不代表必然被吃或多步必杀。只在棋盘或提示阵营改变时重算；选择棋子和时钟消息复用结果。吃子历史每次实际落子都记录，关闭显示不停止记录；悔棋移除被撤销那一步的吃子，重新开局清空。
